# Product Plan

## Goal

Produce a short, decidable delivery plan with product and technical ownership.

## How

1. The controller delegates product documents to PM and technical scope to the project's TL. PM owns product docs. TL drafts tasks and does not write source.
2. PM returns the outcome, user-facing scope, and any proposed product-document changes. TL returns changed roots, test approach, exclusions, and cross-project needs.
3. Use CTO only when a real boundary crosses projects. Do not create a new reviewer role or a durable receipt.
4. The controller reads summaries only and asks the human about material unresolved choices.
5. When the human explicitly authorizes product-document changes, PM writes
   the approved document scope. The controller owns Git and tracker writes.
   Do not require AW apply, a receipt, or separate confirmation for each stage.

## Never

- Never require full up-front design for a small, clear change.
- Never let PM write source or TL write product docs.
- Never commit, push, close tracker work, or start delivery without scope and authorization.
