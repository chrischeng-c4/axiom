---
id: relay-adopt-libs-operator-deploy-cli
summary: >
  Adopt libs/operator as relay's deploy layer and ship the standard deploy CLI
  (CONTRIBUTING "Deploy artifacts"). A feature-gated src/operator/ module
  defines the Relay CRD (relay.dev/v1alpha1, RelaySpec flattening
  operator::ClusterSpec with shardCount pinned to 1 — relay is a single raft
  group — plus storage/storageClass/graceSecs/logLevel/auth/tokensSecret) and
  a ManagedService impl whose pure render emits via the shared
  operator::render toolkit: ServiceAccount, headless + client Services, PDB,
  and the downward-API StatefulSet through sharded_statefulset injecting
  exactly the env relay's serve reads (POD_NAME/SHARD_COUNT/
  REPLICAS_PER_SHARD/VOTER_COUNT/RELAY_PEER_SERVICE + RELAY_BIND/
  RELAY_DATA_DIR/RELAY_GRACE_SECS, probes /readyz + /healthz on port 7000),
  with optional RELAY_AUTH/RELAY_TOKEN_REGISTRY_FILE Secret-mount wiring
  (lumen's pattern; off unless the CR sets auth: required + tokensSecret).
  The CRD schema is normalized for Kubernetes structural-schema rules
  (uint32/uint64 -> integer + minimum: 0). New CLI verbs on the single relay
  bin — offline render paths always build, only `operator run` needs the
  feature: relay k8s crd|operator|instance render, relay k8s operator run,
  and relay dockerfile render --variant source|release where the committed
  Dockerfile/Dockerfile.release are byte-for-byte fixtures of the render
  (keep #777 pattern). k8s/ base collapses to a small single-node direct
  install (no raft env; production HA goes through the operator CR path via
  instance render --profile prod), k8s/operator/ gains the crd/rbac/
  deployment fixtures, pdb.yaml is deleted, and
  scripts/kind-failover-smoke.sh is rewritten against the single relay image
  with auto-mode env (zero relay-raft references). A private rustls-provider
  feature installs the process-level rustls crypto provider at startup
  (src/tls.rs; enabled by operator/self-update/issue — keep's pattern).
fill_sections: [logic, unit-test, changes]
